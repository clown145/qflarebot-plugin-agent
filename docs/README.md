## 它是什么

一个**运行在 Cloudflare Workers 上**的 QQ 机器人 Agent 插件。它不自己接模型，
而是调用 [`qflarebot-plugin-llm`](https://github.com/clown145/qflarebot-plugin-llm) 提供的 `llm` 服务，
所以模型切换、Key 管理都在那个插件里。

设计上把状态分成三层，每层按宿主的额度特性选存储：

| 数据 | 存哪 | 为什么 |
| --- | --- | --- |
| 会话历史、run 队列、频次窗口 | **Durable Object**（每会话一个） | DO 按 GB-秒计费，每条消息本来就要唤醒它。放这里**每条消息完全不碰 D1** |
| 定时任务、工具开关、Skills、统计、审计 | **D1** | 需要跨会话查询，且写入频率低（配置类） |
| 会话清单（cron 要扫哪些 DO） | **KV** | 只存一个列表，读多写少且写了就去重 |
| 大文件工作区内容 | **R2**（可选绑定） | 超过 8KB 的文本进 R2，不占 D1 单值空间 |

> 这套分层是**按宿主免费版额度反推出来的**，不是随意选的。细节见
> [开发指南 · 存储分层](./development.md#存储分层)。

## 一句话说清的行为

- **群里**：只有 **@机器人** 或以 **唤醒前缀**（默认 `/`）开头才会理，其余一律不回。
- **单聊**：默认任何消息都回（可配置成也要带前缀）。
- **命中指令的不进模型**，两者天然互斥。
- **长会话**超阈值时按「轮」压缩，工具调用和结果永远成对，**不消耗任何 D1/KV 额度**。
- **被频率限制**时回一句提示，不静默丢弃。

## 与 AstrBot / serverless-agent 的关系

- **[serverless-agent](https://github.com/clown145/serverless-agent)**：本插件的 agent loop、
  权限层、VFS、调度、上下文装配都参考了它的结构（三个文件原样复制，见
  [开发指南 · 来源与许可证](./development.md#来源与许可证)）。
- **[AstrBot](https://github.com/AstrBotDevs/AstrBot)**：唤醒判定、人格、`begin_dialogs`、
  上下文压缩（按轮丢弃 + 工具配对修复）、内容安全的双插入点，都对齐了它的语义。

两者都是各自形态下的正确设计，直接照搬会水土不服 —— 具体哪里不能搬、为什么，
写在各自章节里。
