# 工具与权限

## 工具清单

| 工具 | 权限级别 | 副作用 | 前置条件 |
| --- | --- | --- | --- |
| `time.now` | 1 | 无 | — |
| `web.fetch_page` | 1 | 无 | — |
| `search.web` | 1 | 无 | 面板「工具 → 搜索 → 配置」填了 Tavily Key；没填仍注册，调用返回可读错误 |
| `vfs.read_file` | 1 | 无 | 只要 `enable_vfs`（**默认开**）；不绑 R2 走轻量模式，只能读 ≤8KB 文本 |

| `vfs.search` | 1 | 无 | 同上 |

| `vfs.mkdir` | 2 | 工作区写 | 同上 |
| `vfs.move` | 2 | 工作区写 | 同上。改名/移动，目标已存在时失败而不是覆盖 |
| `vfs.delete` | 3 | 工作区写 | 同上 |
| `http.request` | 3 | 外部写 | — |
| `schedule.create` | 3 | 工作区写 | `enable_schedule`（**默认关**） |

| `skills.*` | — | — | 见 [Skills](./skills.md) |

> **`enable_vfs` 默认是开的，且不要求 R2。** 没绑 R2 时走「轻量模式」：
> 文本存在 D1（单条 ≤8KB），大文件直接返回可读错误（提示绑 R2）。
> 详见 [配置说明 → 关于 enable_vfs 的 R2 探测](./configuration.md#关于-enable_vfs-的-r2-探测)。
>
> **工具不见 ≠ 权限不足**：`enable_tools` 是总开关，关掉时全部不注册；
> `enable_vfs` / `enable_schedule` 关掉时对应那组不注册；工具栏里单独关掉的、
> 或人格白名单之外的，也**根本不注册**（模型看不到，也就不会尝试）。

每个工具都能单独开关 —— 见下面的**工具栏**。

## 权限怎么算

两级关卡，**不要混淆**：

1. **QFlareBot 的档位**（`bot_admin` / `group_admin` / `member`）决定**谁能触发命令**。
2. **本插件的 6 级权限**决定**模型能用哪个工具、用到什么程度**。

工具被调用时按下面的顺序判定：

```text
角色基线（default-policy.ts）
   ↓
D1 策略表叠加（{policies}，取并集，只能放宽不能收紧）
   ↓
级别够不够？（requirement.level <= resolved.maxLevel）
   ↓
scope 齐不齐？
   ↓
要不要二次确认？（level>=5 / confirmationRequired / sideEffect==='dangerous'）
   ↓
执行
```

### 角色基线

| 身份 | 级别 | 可用 scope |
| --- | --- | --- |
| 定时任务（`actorId === 'scheduler'`） | 3 | 全开 |
| 群主 / 管理员 | 4 | 全开 |
| 普通群成员 | 2 | 工作区读写 |
| **单聊（`c2c` / `guild_dm`）** | **3** | 工作区读写 + 定时任务 + HTTP |
| 群里角色未知 | 1 | 只读 |

> **为什么单聊给 level 3**：早期单聊用户因为「没有群角色」被判成陌生人（level 1），
> 结果 `schedule.create`、`http.request`、`vfs.write_file` **全部被拒** ——
> 「提醒我三小时后…」这种最典型的单聊用法反而建不出来，**连 Bot 管理员也一样**。
> 能私聊机器人说明这是一条已建立的点对点信道，不是公开群，所以按可用基线处理。
>
> 但**刻意不给 level 4** —— 单聊用户不是群主，不该顺手拿到群管理那档。

### 二次确认：当前是半成品

**协议实现了一半**：

- ✅ `needs_confirmation` 状态、`requiresConfirmation()`、registry 提前返回都在
- ❌ 没有把用户答复变回 `allowDangerous: true` 的通道

后果：任何 `sideEffect: 'dangerous'` 或 `level >= 5` 的工具会**永久卡在待确认**。
目前没有这种工具（最高级别是 3），所以是**潜在问题而非现行故障**。

如果你要加一个危险工具，得先把这个闭环补上 —— 光声明 `sideEffect: 'dangerous'`
只会让它永远不可用。

### 策略表（`{policies}`）没有写入方

D1 里建了 `{policies}` 表，解析代码也会读它、叠加它，但**全仓库没有一条
INSERT/UPDATE**，面板也没有入口。

所以**当前的真实行为就是上面那张角色基线表**。想用策略叠加只能手工往
`p_agent_policies` 写（`{policies}` 由框架展开成 `p_agent_<表名>`）。

另外注意：叠加逻辑用 `Math.max` **取并集，只能放宽不能收紧** ——
需要「某个群禁用某工具」这种收紧场景，应该用工具栏的开关，不是策略级别。

## 工具栏（单工具开关）

管理页可以逐个关掉不想让模型用的工具。关掉的工具**根本不注册** ——
模型看不到它们，也就不会尝试调用后被权限拒绝（那样既费 token 又让模型困惑）。

**存储**：D1 单行（`{tool_settings}`，主键固定 `default`）。
设计约束是 D1 写额度全机器人共享 10 万行/日，而工具开关几乎不变，
所以「一行、UPSERT、`WITHOUT ROWID`」是最省的形式。

关掉某个工具后，下一轮对话立即生效（每次 `buildRegistry` 时读一次设置）。

> 优先级：**工具栏开关 > 权限级别**。关掉是硬关，权限再高也用不了。

### 实现细节（为什么是「最后统一过滤」）

开关不是在每个 `push` 前面判断的，而是在 `buildRegistry` **末尾统一过滤**。
这样新增工具时不必记得还要处理开关，漏一处的风险归零。

而且**必须过滤后再取 `registry.list()`** —— 提示词里的「工具使用规范」用的是
同一个列表，先取再过滤会让模型看到被关掉的工具并去调用，然后被白名单拦下。

### 在哪改

**管理页「工具」区块**：一行一个工具，右侧开关。关掉的整行压暗并划线，
所以「哪些没开」一眼可见，不用逐行读开关状态。勾/取消勾**立即保存**。

每行显示：工具名、描述、权限级别（翻译成人话：只读 / 写工作区 / 有副作用 / 群管理）、
副作用标签（外部写 / 危险）、以及需要的 scope。

### 接口

```text
GET  /api/tools    → { tools: [...], disabled: [...] }   # 返回完整列表，enabled 标记状态
POST /api/tools    → { disabled: [...] }                 # 设置关掉哪些
```

GET 返回的是**未过滤**的完整列表：被关掉的工具也要出现，否则页面上就再也
点不到「重新开启」了。

> 页面数据走 `/api/overview`（它把 tools 一起带回来了），避免打开页面时再多一个请求。

## 安全防线

| 防线 | 覆盖 | 说明 |
| --- | --- | --- |
| **SSRF 防护** | `http.request` / `web.fetch_page` / 图片下载（`agent/media.ts`） | 拦截 localhost、私有/保留 IPv4、链路本地、CGNAT、IPv6 映射/兼容/NAT64 地址；**每一跳重定向都重新校验**。**不解析 DNS**，见下方限制 |
| **响应体积上限** | http 1MB / web 2MB / search 512KB | 防止一个大响应吃光 128MB 内存 |
| **工具超时** | 每个工具自带 `timeoutMs` | 超时返回 `timeout` 结果，不吊死整个 run |
| **工具白名单** | loop 内 | 模型编出的工具名会被拦下 |
| **权限级别 + scope** | 每次调用 | 见上 |
| **内容安全** | 入站 + 出站 | 见[配置说明](./configuration.md#内容安全) |
| **频率限制** | 每会话每分钟 | 见[配置说明](./configuration.md#频率限制) |

### 关于 SSRF 的两个细节

**① `redirect: 'follow'` 是不能用的。**
攻击者可以让你请求一个公网地址，然后 302 到 `http://169.254.169.254/`（云元数据）。
所以三个抓取路径都是**手动逐跳**：每次 `redirect: 'manual'`，拿到 `Location`
重新校验再跟，最多 3 跳。这条漏过两次：

- `web.ts` 早期版本用了 `follow`（已修，有单测）；
- **图片下载**（`agent/media.ts`）一直是 `fetch(url, { redirect: 'follow' })`：
  不校验、不逐跳、**无超时**（一张挂住的图能吃光 30 秒事件预算）。
  图片 URL 来自消息正文，可以被伪造。现在它复用 `validateFetchUrl` +
  `manual` 逐跳 + `AbortSignal.timeout`。

**② 明确的限制：不做 DNS 解析，因此不防 DNS rebinding。**

`src/tools/http/url-safety.ts` 只对**字面量**做判断（IP、`localhost`、`*.localhost`），
**不发 DNS 查询**。所以下面这些拦不住：

- `http://169.254.169.254.nip.io/`（公有域名解析到内网地址）；
- DNS rebinding（校验时解析到公网、fetch 时解析到内网）；
- 任何「域名 → 内网 IP」的映射。

不解析的理由：Worker 里没有同步 DNS；每次抓取多做一次查询既费子请求额度，
又仍有 TOCTOU 窗口，只能算提高门槛、不能算防住。
**真正的防线在网络层**（Cloudflare 的出口访问控制 / 不要把元数据服务暴露给 Worker），
这里的名单只是纵深防御的一层。别把它当成完整的 SSRF 防护。

当前拦住的段（`url-safety.ts` 里有逐条注释与单测）：

| 类别 | 网段 |
| --- | --- |
| IPv4 本网 / 私网 / 回环 | `0.0.0.0/8`、`10/8`、`127/8`、`172.16/12`、`192.168/16` |
| IPv4 链路本地（云元数据） | `169.254/16` |
| IPv4 CGNAT | `100.64/10` |
| IPv4 保留 / 测试段 | `192.0.0/24`、`192.0.2/24`、`198.18/15`、`198.51.100/24`、`203.0.113/24` |
| IPv4 组播 / 保留 | `224.0.0.0/4`、`240.0.0.0/4`（含广播） |
| IPv6 回环 / 未指定 | `::1`、`::` |
| IPv6 私网 / 链路本地 / site-local | `fc00::/7`、`fe80::/10`、`fec0::/10` |
| IPv4 藏进 IPv6 | `::ffff:a.b.c.d`（映射）、`::a.b.c.d`（兼容）、`64:ff9b::/96`（NAT64） |

## 工具结果怎么回给模型

工具结果序列化后作为 `role: 'tool'` 消息回填，然后**把整个消息数组重新发给模型**
（不是增量补丁）。

**有硬上限**：`max_model_steps`（默认 8）和 `max_tool_calls`（默认 12）。
超限是**直接抛错并告知用户**，不是静默截断 —— 静默截断会让用户以为任务做完了。

**注意**：累计的工具结果**字节数没有上限**，只有上面两个次数上限。
一个返回巨大内容的工具可能把上下文撑爆 —— 这是 `max_context_tokens` 压缩要解决的问题。
